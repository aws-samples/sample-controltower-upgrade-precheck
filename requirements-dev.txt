# Pinned development / CI dependency set.
#
# Why this exists separately from requirements.txt
# ------------------------------------------------
# requirements.txt declares `boto3>=1.34.0` - a floor, deliberately. The tool's own preflight
# checks whether the installed SDK exposes the Control Tower baseline APIs and tells the user to
# run `pip install -U 'boto3>=1.34'` when it does not, so freezing users to a single boto3 would
# work against the tool. Runtime therefore stays a range.
#
# A `>=` range is, however, unresolvable to dependency-scanning tools. Software composition
# analysis (for example `trivy fs --scanners vuln`) cannot pick a concrete version, so it scans
# nothing and reports no findings - which is not the same as reporting no vulnerabilities. Pinning
# here gives CI a reproducible environment and gives scanners a resolvable target, without
# constraining anyone who just wants to run the tool.
#
# Usage:  pip install -r requirements-dev.txt
